# Development roadmap

1. **Playable training prototype — implemented:** procedural facility, Rapier movement, resettable targets, health/hazards, scoring, HUD, menus, pause and saved settings.
2. **Enhanced combat — implemented:** pistol, blade, rifle, shotgun, independent magazines, recoil/reload/melee/equip animations, auto reload, hit feedback, Dash, Shield, Scanner and EMP. The drone/Sparring entry has now been removed; practice uses multiplayer-shaped robot targets with head/body/limb/foot damage. Hands-on balancing and target-laptop performance testing remain.
3. **Private 1v1 multiplayer — core gameplay implemented:** private rooms, invite codes, ready/countdown, opposite spawns, server-owned movement/collision, remote interpolation, all four weapons, validated regional hits/cover/range, cooldown/ammo/reload enforcement, confirmed HUD feedback, kills/deaths, three-second respawns, reconnect freezing and arena disposal/re-entry. All four online abilities now have server validation, cooldowns, collision-safe dash, shield absorption, scanner reveal, EMP disruption and synchronized effects. Best-of-three matches now include host-selected format, first-to-two wins, timed rounds/draw replay, intermission/countdowns, fresh round loadouts, scoreboard, forfeit handling, results and rematches. Free Play remains selectable. See [lobby setup](PRIVATE_LOBBIES.md) and [online combat](ONLINE_ARENA.md).
4. **Accounts/loadouts — implemented and connected:** Supabase email/password Auth, confirmation/recovery, saved callsigns, cross-device equipment, statistics and Row Level Security. Guest equipment saves locally. The selected project-duel database and real browser Auth/profile/loadout flows are verified. Keep privileged credentials on the server. General-user email delivery requires custom SMTP; see [setup](ACCOUNTS_AND_RANKINGS.md).
5. **Maps — implemented:** host-selectable Training Facility, Neon District and Orbital Station, with procedural themes and shared server/render collision and shot occlusion. New multiplayer hazards remain optional future work.
6. **Competitive features — core implemented and verified live:** verified result snapshots, private history, wins/losses/win rate, Elo rating, leaderboard, casual/rated selection, short-game/repeated-pair limits and a durable server retry queue. Public matchmaking, seasons and stronger anti-collusion controls remain future work.
7. **Combat audio — implemented:** generated weapon/equip/reload sounds, confirmed hits/headshots/eliminations, damage, abilities, footsteps, round/results cues, positional opponent sounds, saved volume/mute, preview and focus/pause handling. No external sound assets or additional dependency. See [audio](AUDIO_SYSTEM.md).
8. **Deployment:** persistent multiplayer hosting, HTTPS/WSS, configuration, security and measured performance. Persistent servers may require paid hosting.

Next: configure SMTP for confirmation/reset emails to players outside the Supabase team. Local Auth redirects, server credentials and a live account/match check are complete for project-duel. Deployment needs persistent server storage and HTTPS/WSS. Movement prediction and hit rewind can improve latency while preserving server authority. Local robot training stays available without a backend. Arena recovery across page reloads, hands-on balancing and laptop profiling remain outstanding.
